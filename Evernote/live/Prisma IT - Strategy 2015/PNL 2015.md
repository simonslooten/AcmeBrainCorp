# PNL 2015

2015

	
	
	
	

	
	
	
	
Every software company needs to continuously reinvent itself. In fact, it’s not only software companies that face this problem, car manufactures who would still produce horse carriages, would be out of business. The only difference is that we tend to move faster.

	
	
	
	

	
	
	
	
Prisma IT has always done this by scouting the market, finding an opportunity (programming language or other), start to work with it, start delivering training, find customers who wanted software build with these tools and then adapt in the organization. This was the case with ColdFusion, Flex, LiveCycle, Mura, frameworks etc.

	
	
	
	

	
	
	
	
The reason why we have always succeeded is that there would always be one person, who would be the “evangelist” of the new language. For CF 
&
 Flex that person was me, for LiveCycle it was Jochem, for frameworks Mark would often be an evangelist. Ron for Brightcove and for Mura it is Guust.

	
	
	
	

	
	
	
	
In the last few years we have not really been able to re-invent ourselves on a continuous basis. And that is starting to worry me more and more.

	
	
	
	
There is an old saying: “if you don’t rewrite your code, someone else will do it for you”. 

	
	
	
	
I believe we have been in the danger zone of “falling behind” for the last 2 or 3 years.

	
	
	
	

	
	
	
	
In the last few years, we have tried to adapt new technologies, but - apart from Mura and Brightcove - we havent really been able to do so. And having said that, I believe Mura and Brightcove aren’t the ones that will be able to “make the difference”. They are nice, but they will not be the big differentiators to get us into and through 2015 and further.

	
	
	
	

	
	
	
	
Mendix, AWS training, BonitaSoft, DataLogics, DocOrigin are all technologies that we have not been able to adapt to and, as a result, we let them slip.

	
	
	
	

	
	
	
	
If Prisma IT wants to survive and lead in this continuously faster moving world, we need to change our model and adapt faster and with more conviction to changes and new oportunities.

	
	
	
	

	
	
	
	
For the next years, We need to have a discussion and build a plan around the idea to become a “Cloud Architected Software” centric company.

	
	
	
	

	
	
	
	
What I have seen in the last few days from AWS blew my mind. for the first time in over 14 years and for the 5th time in my career, I believe we found something that can help us push ourselves to the next stage. After DEC VAX, Apple Macintosh, ColdFusion and Flex, I believe Cloud centric (or cloud architected) *we need to find a better term* development will completely change the paradigm of software development.

	
	
	
	

	
	
	
	
Our partner of choice is AWS.

	
	
	
	

	
	
	
	
Over the last couple of years, AWS has been handled by us on the level of system management. We build applications, hand them over to sysmngmnt and they deploy. Either on our own hardware or in the cloud.

	
	
	
	

	
	
	
	
We need to rapidly change this model. “Cloud awareness” needs to become cloud architected and needs to be handled at the architect level. We need to start designing and architecting our applications (projects, existing projects and repeatable solutions) around the possibilities that AWS provides.

	
	
	
	

	
	
	
	
We also (and at the same time) need to change the way we develop. AWS tools like AWS CodeCommit, CodeDeploy CodePipeline, AWS Container Service, Docker and Apollo all need to be at the heart of our development methodologies.

	
	
	
	

	
	
	
	
Running the apps we build on AWS will be the standard.

	
	
	
	

	
	
	
	
Technologies like AWS Lambda will fundamentally change the way we build software.

	
	
	
	

	
	
	
	
At the same time we need to start projects and programs with sales and marketing to start talking to customers, add content on our website etc.

	
	
	
	

	
	
	
	
We need to come up with a way to be able to adapt to new technologies and features that AWS releases. Just as an indication of the speed they are approbating: AWS has released more than 500 new technologies and features since Jan 1 2014!

	
	
	
	
And the scary thing is that they build up even more speed with their releases.

	
	
	
	

	
	
	
	
This will be a huge project for 2015 and it will mean that everybody needs to commit to this.

	
	
	
	
We need to do this. It will be hard work and fun and it will make us better.

	
	
	
	

	
	
	
	
I have created this text as the start of an internal discussion with management, team leads, developers and sysmngmnt on how to do this.

	
	
	
	

	
	
	
	
We can not afford to miss this one and we cannot afford to wait another year.

We need to rapidly change this model. “Cloud awareness” needs to be handled at the architect level. We need to start designing and architecting our applications (projects, existing projects and repeatable solutions) around the possibilities that AWS provides.

	

	
We also (and at the same time) need to change the way we develop. AWS tools like AWS CodeCommit, CodeDeploy CodePipeline, AWS Container Service, Docker and Apollo all need to be at the heart of our development methodologies.

	

	
Running the apps we build on AWS will be the new normal.

	

	
Technologies like AWS Lambda will fundamentally change the way we build software.

	

	
At the same time we need to start projects and programs with sales and marketing to start talking to customers, add content on our website etc.

	

	
We need to come up with a way to be able to adapt to new technologies and features that AWS releases. Just as an indication of the speed they are gaining: AWS has released more than 500 new technologies and features since Jan 1 2014.

	
And the scary thing is that they build up even more speed with their releases.

	

	
This will be a huge project for 2015 and it will mean that everybody needs to commit to this.

	
We need to do this. It will be hard work and fun and it will make us better.
